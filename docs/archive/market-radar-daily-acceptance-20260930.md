## 2. 实现与迁移

- 新增最小 `runtime.py`、`schedule.py`、`daily.py` 与 `sync_market_daily.py`，七个写入入口共用目录校验和进程锁；业务采集复用既有六个服务，无新增依赖。
- 增加 `daily_sync_attempts`、`daily_sync_worker`，记录尝试预算、运行心跳、失败及恢复事实；快照继续与来源成功审计原子发布。
- 固定顺序为价格、宏观、经济事件、基本面、盈利、宽度。到期目标来自既有 XNYS 日历；旧价格不得冒充目标日，暂时失败有限重试，独立来源继续执行。
- `GET /api/market-radar/sync-status`、价格/宽度新鲜度及雷达页每分钟自动重读已接入。后台暂停、切回/重连重读和 UTC 午夜事件窗口刷新有测试覆盖。

正式路径为 `runtime/market-radar/catalog/eodhd`、`runtime/market-radar/data/market-radar.db` 和 `runtime/market-radar/reports`。旧市场库经 SQLite backup 备份与迁移；十四张旧表行数保持一致，原 12 条来源审计保留，新增两张运行表后完整性检查为 `ok`。验收结束再次逐表比较原市场库与备份，十四表全部内容一致。

新 Catalog 从真实供应商重建，没有在线复制 paper Catalog，也未删除 826 原始数据或其他业务数据。Web 只读挂载新雷达 data，正式 API 返回的日期和快照时间与新库对应。证据：`migration.json`、`preservation-check.json`、`database-final.json`、`formal-api-final.json`。

## 4. 唯一写入者与恢复边界

真实探针发现 Docker Desktop 的容器锁与 macOS 宿主 `flock`、POSIX 锁不互通。仅有内核锁不足以保护同一 bind mount，因此在既有 `runtime.py` 内补充 `.platform` 独占创建绑定：首次绑定写入平台，异平台在业务 IO 前拒绝；同平台仍按实际数据库与 Catalog 两项资源持内核锁。

正式目录已绑定 Linux 容器。宿主 Python 探针被明确拒绝，第二个容器写入入口被进程锁拒绝；两次拒绝没有新增业务尝试或成功批次。锁测试只验证所有权，没有另起真实采集。原跨环境缺口证据与修复后证据均保留：`cross-environment-lock.json`、`host-writer-guard.json`、`second-container-writer.log`。

绑定退出后保留，不通过租约、PID 或超时猜测能否接管。正式域使用容器 CLI 维护；需要跨平台迁移时先停全部旧写入者，再转入新目录。不能在线删除绑定或 Catalog 中断标记。

隔离测试覆盖两项资源锁、真实子进程中断、Catalog 未完成标记、来源成功但每日记账前崩溃、重启预算不清空、晚到价格/FRED、429、认证失败、休眠与跨日。06:00 前不会因 UTC 午夜重复采集已满足的计划日；提前恢复采得的当天当前快照可以由当天 06:00 计划复用。
