# 826 剩余生产验收计划

整理日期：2026-09-29；依据截至 2026-09-28 的验收记录。本计划提取已确认方案的未完成要求，不新增交易方式、代码改动或故障演练授权。最新完成情况统一见[进度页](../status.md)。

## 范围与依据

继续使用固定 826 release、十只目标、既有风控和 IBKR paper auto 通路，实盘关闭、Bot 不参与。获批代码方案及原完成标准保留在[原实施方案](../archive/826-ibkr-paper-daily-implementation-plan.md#十验收标准)。真实输入、首次成交、受控重启、恢复代码和 D25 买入的既有通过结果保留，不为了补文档重放已提交工作流。

## 连续五个交易日

按连续五个常规交易日逐日保留以下事实，使用同一份两侧联合证据完成 FD-02 时效和 FD-04 连续生产的剩余验收：

1. FacDigger 实际生产的 D、固定 release、delivery、完整目标身份、score/eligible、日历与质量门禁结果，来源为 `signal_inference`。
2. 发布、发现、行情准备、Catalog 写入、HeyBoss 接纳完成的实际 UTC 时间；接纳严格早于 N 开盘。记录耗时和重试，首次历史补数单列，不当作每日耗时。
3. 当日自然信号及完整执行窗口、D 参考价、账户/持仓核对、提交前风控与 auto 批准；无订单时记录目标已满足或合法 SKIP 的具体依据。
4. 每笔订单终态、原始成交、费用和成交后持仓，核对数据库、NT 快照与独立券商回报一致；重复轮询和恢复不重复提交。
5. 正式 API 与实际网页正确展示决策、订单、成交、持仓和来源时间，原 826 回测及其他业务仍可访问；本地采样不冒充新券商回报。

持续缺输入、采集/推理失败或超时 SKIP 不算跑通。故障演练导致的预期 SKIP 单独标注，不能拿离线 fixture、historical 接纳或本地撮合补齐生产天数。已有单日证据只有在日期确实连续、内容完整时才能纳入同一观察窗口。

## 恢复旧仓卖出的真实验证

等待后续合法自然批次确实要求卖出恢复的旧持仓。核对提交绑定经审计确认的实际 PositionId，原始成交后对应持仓正确减少或清空；如还有买入，必须在卖单全部终态后按实际持仓重新计划。最终核对券商、Cache、原始成交净数量、正式审计与网页一致。

这一项可以与上述五日窗口同时完成；若期间没有自然卖出，明确保留未验收，不手工制造订单、不改因子目标、不重置 D24/D25。9 月 25 日故障前的卖出及修复后的离线成交不能替代本项。

## 联合边界与异常处理

- 共同日历固定样例和完整区间一致性检查继续保留；更换日历实现或升级相关依赖时重跑，具体入口见[因子参考](../reference/factor-integration.md#统一日历缺分保护与恢复2026-09)。
- FacDigger 负责生产、质量门禁、按时发布和其部署。发现上游缺口记入[FD 记录](facdigger-826-paper-production-gaps.md)，由对应项目修改，HeyBoss 不放宽交付校验。
- 出现执行或持仓一致性异常时保护性停止唯一交易节点，保留其他服务和证据；按[恢复指引](../operations/paper.md#故障与恢复)核对。代码修复仍按项目约束先确认方案。
- 不重放已提交或状态不明的订单，不直接修改正式审计，不恢复交易前旧库来补验收。会话健康、订单提交和成交完成分别判断。

## 记录与完成

逐日结论使用明确日期，附 D/N、输入时效、执行或无需下单原因、核对结果及剩余项；原始券商信息、数据库备份、截图和机器输出保存在私有 `runtime/reports/paper/826/`。文档只保存脱敏结论及证据位置，不建立第二套业务账本。

完成后把该阶段验收记录放入[归档目录](../archive/README.md)，更新[进度页](../status.md)及相关 FD 状态。只有五日证据完整且恢复旧仓卖出的真实验证完成，才能关闭这两项剩余验收。账户整体净值与 826 策略表现分开，资金变化、存量仓位和市价跳空如实说明，盈利不作为通过门槛。
